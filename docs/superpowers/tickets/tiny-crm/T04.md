## Acceptance criteria

- `Infrastructure/SessionAuthAttribute.cs` — `ActionFilterAttribute` that checks `Session["UserId"]`; on missing, redirects to `/Account/Login?ReturnUrl=<requested>`.
- `AccountController` (no `[SessionAuth]`):
  - `GET Login` renders form with username/password fields + `@Html.AntForgeryToken()` + `ReturnUrl` query capture.
  - `POST Login` validates against `UserRepository.GetByUsername`, BCrypt-verifies password, stores `UserId/Username/Role` in Session, redirects to `ReturnUrl` or `/Dashboard`. On failure re-renders with error.
  - `GET Logout` calls `Session.Abandon()`, redirects to Login.
- `Views/Account/Login.cshtml` uses `_LoginLayout` (bare, no navbar).
- Login with `admin`/`Admin@123` succeeds and sets session.
- Wrong credentials re-render login with validation summary.
- Hitting a protected route unauthenticated redirects to login with `ReturnUrl`.
