## Acceptance criteria

- `CustomersController` (`[SessionAuth]`) implements:
  - `GET /Customers` — paginated list (10/page via Skip/Take), shows Name/Email/Phone/Company/Status + action links.
  - `GET /Customers/Create` — form with Status dropdown.
  - `POST /Customers/Create` — DataAnnotations validation, insert with `CreatedByUserId` from session, redirect to list.
  - `GET /Customers/Edit/{id}` — pre-filled form.
  - `POST /Customers/Edit/{id}` — update, set `UpdatedAt`, redirect to list.
  - `GET /Customers/Details/{id}` — customer info (interaction history stub left for T07; this ticket renders customer info only).
  - `POST /Customers/Delete/{id}` — delete (cascade handled by SQL), redirect to list.
- `Views/Customers/Index.cshtml` — table with Bootstrap pagination.
- `Views/Customers/Create.cshtml` + `Edit.cshtml` — form with jQuery unobtrusive validation.
- `Views/Customers/Details.cshtml` — customer info card (interaction list added in T07).
- Create → Details → Edit → Delete all work against seeded/created customers.
